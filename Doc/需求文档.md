# NewLife.JT1078 需求文档

> 版本：v1.0 | 日期：2026-07-12

本文档描述 NewLife.JT1078 的愿景、核心目标和功能方向。完成状态在[功能清单](功能清单.md)中追踪，详细设计在[架构设计](架构设计.md)中展开。

## 1. 背景与愿景

### 1.1 背景

JT/T 1078-2016《道路运输车辆卫星定位系统 视频通讯协议》是交通运输部发布的行业标准，规定了道路运输车辆卫星定位系统中车载视频终端与监控平台之间的音视频通信协议。该协议基于 RTP（Real-time Transport Protocol），定义了音视频流的封装、传输和控制指令。

### 1.2 愿景

为 .NET 生态提供完整、高性能、跨平台的 JT/T 1078 协议实现，让开发者能够快速构建车载视频监控平台，覆盖协议解析、编解码、转封装、服务端全链路。

### 1.3 目标用户

| 角色 | 需求 |
|------|------|
| **协议库使用者** | 直接引用 NuGet 包，解析/构建 JT1078 RTP 报文 |
| **音视频平台开发者** | 基于本库实现 JT1078 终端接入、流媒体转发 |
| **设备接入开发者** | 使用服务端组件快速搭建 TCP 1078 监听服务 |

## 2. 功能需求

### M1 RTP 协议解析

**优先级**: P0（核心）

| 需求编号 | 描述 | 验收条件 |
|----------|------|----------|
| M1-1 | 完整解析 JT1078 RTP 报文头部 | 能正确读取所有固定字段和条件字段 |
| M1-2 | 构建 JT1078 RTP 报文 | 能正确写入所有字段，生成合规的二进制数据 |
| M1-3 | 支持所有 29 种音视频编码类型 | AVTypes 枚举覆盖 JT/T 1078 定义的全部类型 |
| M1-4 | 支持所有 5 种数据类型 | I帧/P帧/B帧/音频帧/透传数据 |
| M1-5 | 支持分包标记（原子包/首包/末包/中间包） | PacketFlags 枚举完整映射 |
| M1-6 | TCP 粘包处理 | JTCodec 能正确处理 TCP 流中的多个报文 |

### M2 音频编解码

**优先级**: P0（核心）

| 需求编号 | 描述 | 验收条件 |
|----------|------|----------|
| M2-1 | G.711A 编解码 | A-law ↔ PCM 16bit 双向转换 |
| M2-2 | G.711U 编解码 | μ-law ↔ PCM 16bit 双向转换 |
| M2-3 | ADPCM 编解码 | IMA-ADPCM ↔ PCM 双向转换 |
| M2-4 | 海思芯片头处理 | 自动识别并剥离/添加 4 字节海思头 |
| M2-5 | 音频编解码工厂 | 根据 AVTypes 自动选择编解码器 |

### M3 H.264 视频解析

**优先级**: P0（核心）

| 需求编号 | 描述 | 验收条件 |
|----------|------|----------|
| M3-1 | NAL 单元定位与分割 | 基于起始码 `00 00 01` / `00 00 00 01` 正确分割 |
| M3-2 | NAL 单元头解析 | 正确读取 forbidden/ref/nutype |
| M3-3 | SPS/PPS 提取 | 正确识别并存储 SPS/PPS NAL 单元 |
| M3-4 | 视频宽高解析 | 从 SPS 中通过 Exp-Golomb 解码提取宽高 |
| M3-5 | Profile/Level 解析 | 正确提取 profile_idc/level_idc |
| M3-6 | 竞争字节剥离 | 正确处理 `00 00 03` 转义序列 |

### M4 FLV 转封装

**优先级**: P1

| 需求编号 | 描述 | 验收条件 |
|----------|------|----------|
| M4-1 | FLV 头部生成 | 签名、版本、音视频标志位正确 |
| M4-2 | Script Tag（元数据） | 包含宽高、帧率、编码格式等 onMetaData |
| M4-3 | 视频 Tag 编码 | H.264 NAL 转 AVC Video Tag（含 AVCDecoderConfigurationRecord） |
| M4-4 | 音频 Tag 编码 | 音频帧转 Audio Tag（含 AudioSpecificConfig） |

### M5 fMP4 转封装

**优先级**: P1

| 需求编号 | 描述 | 验收条件 |
|----------|------|----------|
| M5-1 | ftyp Box 生成 | 品牌和兼容品牌正确 |
| M5-2 | moov Box 生成 | 包含 trak（video/audio）完整轨道信息 |
| M5-3 | moof+mdat 分段生成 | 每个 GOP 生成一对 moof+mdat |
| M5-4 | avcC Box（AVC Configuration） | 正确封装 SPS/PPS |

### M6 JT1078 消息类型

**优先级**: P1

| 需求编号 | 描述 | 验收条件 |
|----------|------|----------|
| M6-1 | 0x9003 查询终端音视频属性 | 空体消息 |
| M6-2 | 0x1003 终端上传音视频属性 | 完整字段解析 |
| M6-3 | 0x9101 实时音视频传输请求 | 含服务器IP、端口、通道等字段 |
| M6-4 | 0x9102 音视频实时传输控制 | 含关闭/切换/暂停等指令 |
| M6-5 | 0x9201 远程录像回放请求 | 含时间范围、倍速、存储类型 |
| M6-6 | 0x9202 远程录像回放控制 | 含控制指令、拖动时间 |
| M6-7 | 0x9205 查询资源列表 | 含通道、时间、报警标志 |
| M6-8 | 0x1005 终端上传乘客流量 | 含人数统计等 |
| M6-9 | 0x1205 音视频资源列表应答 | 含资源项列表 |
| M6-10 | 0x1206 文件上传完成通知 | 含文件名、MD5 等 |
| M6-11 | 0x9105 音视频传输状态通知 | 含丢包率、误码率 |
| M6-12 | 0x9206 文件上传指令 | 含 FTP 地址、凭据 |
| M6-13 | 0x9207 文件上传控制 | 含控制指令 |

### M7 TCP 服务端

**优先级**: P2

| 需求编号 | 描述 | 验收条件 |
|----------|------|----------|
| M7-1 | TCP 1078 端口监听 | 基于 NewLife.Net 的 NetServer |
| M7-2 | RTP 分包合并 | 按 SIM+通道缓存，自动合并首/中/末包 |
| M7-3 | JTCodec 粘包处理 | 集成编解码器处理 TCP 流 |
| M7-4 | 会话管理 | 终端连接/断开会话生命周期管理 |

## 3. 非功能需求

| 编号 | 类别 | 要求 |
|------|------|------|
| NFR1 | 性能 | 核心路径使用 Span\<T\> 零分配解析，ArrayPool 缓冲区池化 |
| NFR2 | 跨平台 | 支持 .NET Framework 4.5+ / .NET Standard 2.0+ / .NET 6+ |
| NFR3 | 低依赖 | 核心库仅依赖 NewLife.Core，无第三方依赖 |
| NFR4 | 兼容性 | 协议实现与 JT/T 1078-2016 标准完全一致 |
| NFR5 | 可测试性 | 核心模块均可独立测试，编解码器支持往返验证 |
| NFR6 | 文档 | 所有公共 API 包含 XML 文档注释 |
