# 多语言本地化

本仓库的异常、日志与程序集元数据统一使用 NewLife.Core 的运行时本地化机制：**英文原文为键与兜底**，`Locales/*.yml` 在编译期校验、压缩并内嵌，运行时按 `CultureInfo.CurrentUICulture` 查表。不依赖 resx 与卫星程序集，单 DLL、AOT 安全。

## 1. 词表位置与语言

| 程序集 | 词表目录 | 语言数 | 说明 |
|--------|----------|--------|------|
| `NewLife.JT1078` | `NewLife.JT1078/Locales/` | 10 | 协议异常消息、程序集标题与描述 |
| `NewLife.JT1078.Server` | `NewLife.JT1078.Server/Locales/` | 10 | 服务端日志消息、程序集标题与描述 |
| `NewLife.JT1078.Web` | `NewLife.JT1078.Web/Locales/` | 10 | 控制器提示消息 |

语言集合与 README 的 11 种语种对应（英文为源文，不建 `en.yml`）：`zh-Hans`、`zh-Hant`、`es`、`de`、`ja`、`fr`、`pt`、`ru`、`ko`、`ar`。新增语言时三处词表必须同时补齐，键集合完全一致。

## 2. 三类文本的处理边界

| 类型 | 源文 | 词表 | 示例 |
|------|------|------|------|
| 运行时消息（异常、日志、接口提示） | 英文 | 全部目标语言 | `"The message must be JTMessage."` |
| 程序集与 NuGet 元数据 | 英文（`AssemblyTitle`/`Description`） | 本程序集词表；`PackageDescription` 中英双语 | `"NewLife JT1078 Server"` |
| 实体/控制器元数据（本仓暂无） | 项目母语 | 目标语言 + `en` | 下游数据类库的 `DisplayName` |

- 运行时消息**禁止字符串插值**，必须写成格式字符串 + 参数，否则模板已展开、无法查表。
- 日志实例前缀由 `XTrace.Log.InfoPrefixed(prefix, format, args)` 在翻译之后拼接，不要手工拼进模板。
- 参数值不翻译；需要整句本地化时拆成多条完整英文消息。

## 3. 代码写法

| 场景 | 写法 |
|------|------|
| 自定义异常（`XException`） | 构造器自动翻译，词表需有对应键 |
| BCL 异常 | `throw new InvalidOperationException(L.T("..."))` |
| 日志 | `XTrace.Log.Info("...", args)` / `XTrace.Log.InfoPrefixed("Prefix", "...", args)` |
| 手工翻译 | `L.T(...)`（界面/异常）、`L.TLog(...)`（日志语言） |
| 无词表的程序集（如 Client） | `Localization.Translate(...)`，英文兜底 |

`Localization.Culture` 控制异常与常规文本，`Localization.LogCulture` 控制日志与配置注释，两者相互独立。

## 4. 校验与测试

```bash
# 三个程序集的键集合、占位符、格式说明符、孤儿键、L.T 缺词条
pwsh -File tools/check-locales-all.ps1

# README 语言切换行与 NuGet 包版漂移
pwsh -File tools/sync-readme-languages.ps1 -Check
pwsh -File tools/sync-readme-package.ps1 -Check
```

- 单元测试 `XUnitTest/LocalizationTests.cs` 覆盖异常翻译、日志语言独立、10 语言译文、占位符格式化与程序集元数据；`XUnitTest/Protocols/LocalizationTests.cs` 覆盖服务端日志词条。
- 归入 `[Collection("GlobalState")]` 串行执行，避免全局语言状态竞争。
- **词表注册依赖程序集被真正加载**：仅写 `typeof(T)` 可能被 JIT 消除，测试需 `RuntimeHelpers.RunModuleConstructor(typeof(T).Assembly.ManifestModule.ModuleHandle)`。
- AOT 冒烟 `AotSmoke` 覆盖核心库与服务端词表查表，并在全球化不变模式下回退英文源文。

## 5. 常见坑

| 现象 | 原因与处理 |
|------|-----------|
| 翻译不生效，始终英文 | 程序集未加载（模块初始化未执行）；或 key 与源码模板不一致（含隐藏空格）；或用了字符串插值 |
| 构建出现 CS1705 / 运行用旧译文 | 各项目共享 `OutputPath=..\Bin`，升级包后残留旧 DLL；清理 `Bin` 与各项目 `obj` 后重建 |
| 词表文件出现混合换行 | 追加行时用 `\n` 而原文件为 CRLF；统一为 CRLF 后提交 |
| 下游界面显示英文 | 直接读取 `AssemblyTitle`/`Description` 的展示点未调用 `L.T` |
| `check-locales` 报孤儿键 | 源码中已删除的消息未同步删除词条；元数据键用 `metadata-keys.json` 豁免 |

## 6. 与 NewLife.Core 的关系

机制、脚本与规范来自 NewLife.Core 的 `Doc/多语言本地化.md` 与 `Tools/Scripts/`。本仓 `tools/` 内的 `check-locales.ps1`、`sync-readme-*.ps1` 为复用副本（仅调整仓库根定位），Core 升级机制时需同步更新。
